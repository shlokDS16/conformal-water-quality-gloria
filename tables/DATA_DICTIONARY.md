# Data dictionary for the released result tables

This file defines every column of the per-split metrics files (`results/<tag>/metrics_*.csv` in the
Zenodo archive) and every ledger file in `tables/`. It exists because several columns are
method-dependent and cannot be read correctly without their definition: in particular `k_cal`,
whose unit changes with the calibration scheme.

Written for `research/AUDIT_5` finding N6 and `research/REVIEW_full_v2` finding V13.
Generated by hand from `src/run_experiment.py`, `src/run_budget.py`, `src/eval/`,
`src/make_summary.py` and `src/analysis/`, and regenerated only when those modules change.

---

## 1. Ledger files in `tables/`

Every ledger file has the same five-column schema.

| column | meaning |
|---|---|
| `key` | the ledger key. The manuscript quotes no number that is not a `key` in one of these files. Each quoted number carries a `% ledger: <key>` comment next to it in `paper/main.tex`. |
| `value` | the full-precision value. Never rounded in the file. |
| `rounding` | the rule used when the value is printed, for example `3 decimals`, `integer`, `3 significant figures`, `percent, 2 decimals, rounded up`, `percent, 2 decimals, rounded down`. A value printed in the manuscript must follow this rule. |
| `source_file` | the file or glob the value was computed from. |
| `filter` | the row filter applied to that source, and any warning that applies to the key (for example `EXPLORATORY: ... not preregistered`). |

| file | what it holds |
|---|---|
| `summary.csv` | the main per-cell result ledger, one key per (cell, statistic). Cell keys follow the convention in section 3 below. About 212,800 rows, so it ships in the Zenodo archive rather than in the GitHub repository. |
| `derived.csv` | quantities derived from more than one source, or from the run logs: the calibration-budget gap keys `budget.group.*`, the CV+ condition counts `cvplus.gte.*`, the compute keys `compute.*` and the text count `txt.n_interval_methods`. |
| `data_summary.csv` | dataset, quality-control, water-body-grouping, spectral-response and figure-annotation counts (`t1.*`, `t2.*`, `txt.*`, `fig02.*`, `fig04.*`). |
| `h2_power.csv` | everything the manuscript states about the power of the preregistered non-inferiority test H2, under both variance models (`h2.*`), plus the three `cell.*` keys that let a reader rebuild it from the cell-key convention. |
| `confirmatory.csv`, `confirmatory_components.csv` | the 16 preregistered Holm-corrected tests and the arm-level components of the intersection-union tests. Written by the frozen `src/analysis/confirmatory.py`. |
| `exploratory_cells.csv`, `exploratory_budget_group.csv`, `exploratory_budget_local.csv` | exploratory per-cell aggregates and the two calibration-budget grids. Not preregistered. |
| `conditional_shares.csv` | the share of test water bodies below a coverage threshold, per cell. |
| `table*.tex` | the LaTeX table bodies of the manuscript, rendered from the ledgers only. No number is computed in them. |

## 2. Per-split metrics files (`results/<tag>/metrics_*.csv`)

One row per (model, method, alpha) within one split. Point-accuracy rows carry `method = "point"`.

### 2.1 Cell identity

| column | meaning |
|---|---|
| `target` | `Chla`, `TSS`, `aCDOM440` or `Secchi_depth`. All modelling is on `log10` of the target. |
| `sensor` | feature set: `hyp` (405 to 745 nm at 5 nm), `msi` (Sentinel-2A MSI B1 to B6), `olci` (Sentinel-3A OLCI Oa2 to Oa11), `msi_strict` (B1 to B4), `olci_strict` (Oa2 to Oa10). |
| `protocol` | split protocol: `random`, `waterbody`, `waterbody_5km`, `contributor`, `contributor_ds`, `region`, `region_na`. |
| `population` | row population: `primary`, `strict_qc`, `chla_hplc`, `depth_ge3`, `secchi_has_depth`, `exclude_nonpositive`. |
| `noise_mult`, `noise_add` | multiplicative and additive simulated atmospheric-correction noise levels; both 0 outside the noise sweep. |
| `seed` | split seed. The primary cell uses seeds 0 to 19, sensitivity cells 0 to 9. |
| `fold`, `test_unit` | fold index and the held-out unit, for the leave-one-unit-out protocols. |
| `descriptive_only` | `True` when the split carries no coverage guarantee and must not enter a confirmatory test (contributor and region protocols). |
| `tag` | the run tag, for example `core_v2`, `cvplus_v3`, `sens_v2`, `noise_v2`. |
| `code_version` | the code version string written by `src/run_experiment.py`. |
| `model_seed` | the seed given to the model fit, derived from `seed`. |
| `cvplus_row_perm` | present only in `cvplus_v3`: `True` when training rows were permuted per fold fit, which Amendment 5 requires for the Barber et al. (2021) Theorem 4 symmetry condition. |

### 2.2 Set sizes

| column | meaning |
|---|---|
| `n_train`, `n_cal`, `n_test` | rows in the training, calibration and test sets. |
| `n_train_wb`, `n_cal_wb`, `n_test_wb` | distinct water bodies in each. The water-body unit is `wb_group` (2 km linkage), or `wb_5km` under `waterbody_5km`. |
| `n_rows_nonpositive`, `n_rows_nonpositive_test` | rows with a non-positive band value, all rows and test rows. |
| `n_cvplus_wb` | water bodies retained by CV+ after dropping `n mod K` bodies so the folds are exactly equal. |
| `n_cvplus_wb_dropped` | water bodies dropped for that reason. |
| `cvplus_fold_units` | the number of water bodies in each CV+ fold, semicolon separated. Equal by construction. |
| `cv_folds` | number of cross-validation folds: 5 for `gauss`, 10 for `cvplus`, empty otherwise. |

### 2.3 Calibration bookkeeping (read these, not `k_cal`)

`k_cal` is a legacy column: it is the number of scores entering the calibration step, and **its unit
depends on the method**, so it must never be aggregated across methods. Use the explicit columns.

| column | meaning |
|---|---|
| `calib_scheme` | how the calibration scores were formed. One of: `none` (no calibration step: `native`); `pooled_cal_rows` (every calibration row: `scp_pool`, `nscp_pool`, `cqr_pool`, `recal_cal`); `one_row_per_cal_wb` (one subsampled row per calibration water body: `scp_gsub`, `nscp_gsub`, `cqr_gsub`); `oof_groupkfold_train` (out-of-fold residuals from a grouped 5-fold cross-validation on the training set: `gauss`); `holdout_rows_train20` (a 20% row holdout inside the training set: `recal_train20`); `equal_unit_group_cvplus_one_row_per_wb` (one CV+ residual per retained water body, folds of equal size: `cvplus`). |
| `k_cal_rows` | the number of scores, residuals or rows the calibration step actually used. |
| `k_cal_units` | the number of distinct water bodies that contributed them. For `one_row_per_cal_wb` and `cvplus`, `k_cal_rows == k_cal_units`; for `pooled_cal_rows`, `k_cal_rows` is larger. |
| `k_cal` | legacy alias for `k_cal_rows`. Kept for backward compatibility. Do not use it in new analysis. |
| `qhat` | the conformal quantile of the split, on the `log10` scale. Infinite when the rank exceeds the number of scores. |
| `inf_flag` | `True` when the conformal quantile was infinite, that is when `ceil((1 - alpha)(k + 1)) > k`. Such a split covers every test sample by construction, so its coverage of 1.0 is a property of the rule and not of the method. Any coverage reported for a group of splits must carry the number of splits with `inf_flag` set; the manuscript prints that count as an `n∞` superscript. |
| `inf_rate` | the share of test units that received an infinite interval within the split. |

### 2.4 Point accuracy (rows with `method = "point"` only)

Point metrics are written on every row for convenience, but on an interval row they are the metrics
of the **full-training point model**, not of the CV+ fold models. Read point accuracy only from
`method == "point"` rows.

| column | meaning |
|---|---|
| `mdsa` | median symmetric accuracy, per cent. |
| `sspb` | symmetric signed percentage bias, per cent. |
| `logmae`, `logbias`, `logrmse` | mean absolute error, bias and root mean square error on the `log10` scale. |
| `n_fallback_test` | test rows for which the model fell back to the training median. |

### 2.5 Interval metrics

| column | meaning |
|---|---|
| `cov_wb` | **the primary metric**: water-body-averaged coverage. The coverage is computed within each test water body and then averaged over water bodies, so a large water body does not dominate. |
| `cov_pooled` | coverage over test rows, ignoring the water-body structure. |
| `cov_worst_ge10` | the lowest within-body coverage among test water bodies with at least 10 test samples. |
| `n_wb_ge10` | how many test water bodies met that 10-sample threshold, typically 14 to 16. |
| `width_wb` | water-body-averaged median multiplicative width `10^(u - l)`. |
| `width_wb_log10mean` | the same width on the `log10` scale. |
| `width_pooled_median` | median width over test rows. |
| `winkler_wb`, `winkler_pooled` | interval (Winkler) score, water-body-averaged and pooled. Lower is better. |
| `cov_wb_lo`, `cov_wb_hi`, `cov_pooled_lo`, `cov_pooled_hi` | cluster-bootstrap percentile interval for the corresponding coverage, resampling water bodies. Empty when `inf_flag` is set. |
| `beta_mean`, `beta_q_lo`, `beta_q_hi` | mean and quantiles of the finite-sample beta reference law of split-conformal coverage, `Beta(k + 1 - r, r)` with `r = ceil((1 - alpha)(k + 1))` scores, evaluated at the realized `k`. Written for the conformal methods only. This is the law the coverage should follow, not a target the method is aimed at; the ceiling makes the attainable mean coverage step with `k`, which is the sawtooth of the calibration-budget figure. |
| `cvplus_bound` | the numeric Barber et al. (2021) Theorem 4 lower bound on CV+ coverage for this split, computed by `src/conformal/core.py cvplus_bound(n, K, alpha)` with `n` the retained water bodies and `K` the fold count. Written for `cvplus` rows only. |

### 2.6 Timing

| column | meaning |
|---|---|
| `time_model_s`, `time_method_s` | seconds spent fitting the model and forming the interval. |
| `time_lgbm_quantiles_s`, `time_lgbm_cvplus_s` | seconds for the LightGBM quantile fits and for the CV+ fold fits. |
| `time_split_s` | total seconds for the split. Summed over all runs this is CPU-and-GPU occupancy, not elapsed time; the elapsed wall-clock figure is `compute.elapsed_wall_hours` in `derived.csv`. |

## 3. Cell-key convention in `summary.csv`

```
cell.<target>.<sensor>.<protocol>.<population>.<model>.<method>.a<alpha*1000, 3 digits>.<statistic>
```

For example `cell.Chla.hyp.waterbody.primary.lgbm.scp_gsub.a100.cov_wb_mean` is the mean over
repeats of `cov_wb` for chlorophyll-a, hyperspectral features, the water-body protocol, the primary
population, LightGBM with group-subsampled split conformal, at `alpha = 0.10`.

`<statistic>` is a per-split column name from section 2 with a suffix: `_mean`, `_std`, `_p025`,
`_p975`, or `n_splits`, `n_splits_infinite`. A `_p025` / `_p975` pair is the 2.5th and 97.5th
percentile across repeats, which is what the manuscript's whiskers show.

Point-accuracy keys use `<model>.point.point.<statistic>`.

The H2 variance quantities are **not** in `summary.csv`. They are in `h2_power.csv`, both under
`h2.<target>.*` and, for the three that a reader may want under the cell-key convention, under
`cell.<target>.hyp.waterbody.primary.lgbm.scp_gsub.a100.<cov_wb_sd|n_train_wb_mean|n_test_wb_mean>`.

## 4. Calibration-budget grids

### 4.1 `exploratory_budget_group.csv` (calibration water bodies)

One row per (`target`, `sensor`, `population`, `n_cal_wb_target`, `method`, `alpha`).

| column | meaning |
|---|---|
| `n_cal_wb_target` | the budget: the number of calibration water bodies drawn, or `all`. |
| `n_seeds`, `draws_per_seed` | split seeds, and independent calibration draws within each seed. |
| `mean_cov` | mean of `cov_wb` over seeds and draws. |
| `sd_seed_draw0` | standard deviation across seeds using the first draw of each seed, that is the across-split spread at a fixed draw index. This is the spread the manuscript quotes. |
| `sd_seed_means` | standard deviation across seeds of the per-seed mean over draws. |
| `sd_draws_conditional_on_split` | mean within-seed standard deviation across draws, that is the part of the spread caused by the calibration draw alone. |
| `beta_mean`, `beta_sd` | mean and standard deviation of the finite-sample beta reference law at the realized `k`, as in section 2.5. |
| `beta_law_applicable` | `True` only for the subsampled schemes, whose scores are exchangeable across water bodies. Pooled calibration has no finite-sample guarantee under within-body dependence, so a gap from `beta_mean` there measures drift from a law that does not apply, not an error in the rule. The manuscript therefore reports the gap twice, once over the 48 cells where the law applies and once over all 96. |
| `inf_rate_mean` | mean share of test units that received an infinite interval. |
| `mean_width_wb_log10mean` | mean interval width on the `log10` scale. |
| `label` | the run label the rows came from. |

### 4.2 `exploratory_budget_local.csv` (local calibration samples)

One row per (`target`, `order`, `eval_set`, `k`, `score`, `variant`, `alpha`).

| column | meaning |
|---|---|
| `k` | the local budget: samples of the test water body itself added to the calibration set. |
| `order` | which local samples are taken, for example `earliest`. |
| `eval_set` | the evaluation set, for example `common` (the rows common to every `k`, so the curve is comparable across `k`). |
| `score` | the conformity score, `scp` or `cqr`. |
| `variant` | `global`, `augment` (global and local), `local` (local only) or `hybrid`. |
| `mean_cov`, `sd_cov` | mean and standard deviation of `cov_wb` across seeds. |
| `mean_n_wb` | mean number of test water bodies contributing. |
| `inf_rate` | the share of cells that produced an infinite interval. **A row with `inf_rate = 1.0` records an infinite interval, not a coverage of 1.0**, and must be read that way: with `k` local scores and `alpha`, `ceil((1 - alpha)(k + 1)) > k` for every `k < ceil(1/alpha) - 1`, which is 9 at `alpha = 0.10`. Every such row is `mean_cov = 1.0`, `sd_cov = 0.0` by construction. |

### 4.3 `exploratory_cells.csv`

Per-cell aggregates over splits, one row per (`label`, `target`, `sensor`, `protocol`,
`population`, `noise_mult`, `noise_add`, `model`, `method`, `alpha`). Each per-split column of
section 2 appears with the suffixes `_mean`, `_std` and `_median`, plus `n_splits`, `n_seeds` and
`n_splits_infinite` (the number of splits whose `inf_flag` was set). CV+ rows are taken from
`cvplus_v3` only, per preregistration Amendment 5; the unpermuted CV+ rows in `core_v2` are
withdrawn and must not be averaged in.

## 5. What is not in these files

Raw GLORIA reflectance and water-quality measurements are not redistributed. They are obtained from
PANGAEA under the GLORIA licence and must be cited as the dataset record requires. The derived
water-body grouping keys, split definitions and per-split metrics in this release are the only
GLORIA-derived data here, and they are released under CC BY 4.0 (`tables/LICENSE`).
